# 섀도잉 트레이너

상황이 있는 대화를 문장 단위로 따라 말하며 발음을 다듬는 연습 도구입니다.

**자동 채점을 하지 않습니다.** 대신 두 가지로 대신합니다.

1. **원본 → 내 녹음 → 원본** 순서로 번갈아 들으며 직접 비교
2. 문장마다 **발음 유의점**과, 몸으로 확인할 수 있는 **‘맞는지 확인하는 법’**

> 예) `/f/` vs `/p/` — 입 앞 5cm에 종이를 대고 발음하세요.
> `/p/`는 종이가 확 펄럭이고 `/f/`는 거의 움직이지 않습니다.

점수는 스스로 구별하지 못하는 소리를 알려주지 못하고, 초반에 낮게 나와 의욕만
꺾는 경우가 많습니다. 그래서 이 버전은 점수 대신 **자가 검증 방법**을 줍니다.

---

## 난이도 사다리

같은 문장을 발판을 한 겹씩 걷어내며 반복합니다. **잘했다고 평가하면 다음번에
그 문장이 한 단계 어려워집니다** — 복습과 실력 향상이 같은 동작이 됩니다.

| 단계 | 화면에 보이는 것 | 원본 재생 |
|---|---|---|
| 따라 말하기 | 영문 전체 + 한글 | 있음 |
| 키워드만 보고 | **키워드** + 한글 | 있음 |
| 자유롭게 말하기 | **한국어 지시만** | 없음 (녹음 후 공개) |

`자유롭게 말하기` 단계에서는 스크립트와 달라도 틀린 게 아닙니다. 녹음 후
모범 답안 여러 개를 함께 보여줘 "정답은 하나가 아니다"를 눈으로 확인하게 합니다.
상대역 대사는 학습자가 만들어낼 문장이 아니므로 `키워드만 보고`에서 멈춥니다.

**승급 규칙**

```
😀 됐다      → 한 단계 승급, 1일 뒤    (최고 단계면 그대로, 7일 뒤)
😐 그럭저럭  → 단계 유지,   3일 뒤
😖 다시      → 한 단계 강등, 1일 뒤    (최저 '따라 말하기'까지)
```

## 연습할 수 있는 상황

상황을 **주차로 묶어** 순서를 정해뒀습니다. 1주차는 일이 순조롭게 흘러가는
기본 대화, 2주차는 **뭔가 어긋났을 때의 대응**입니다. 실제로 영어가 절실해지는
순간은 후자인데, 언어적으로도 완충 표현·되묻기처럼 한 단계 위를 요구합니다.

**1주차 — 기본기**

| 상황 | 레벨 | 무엇을 익히나 |
|---|---|---|
| 카페에서 주문하기 | A2 | 주문·요청의 기본 어순, `Could I get ~` |
| 호텔 체크인 | A2 | 예약 확인, 요청하기, 숫자·시간 |
| 동료와 주말 이야기 | B1 | 스몰토크 리듬, 축약, 맞장구 |
| 전화로 병원 예약하기 | B1 | 전화 영어 — 시각 단서 없이 듣고 답하기 |

**2주차 — 어긋났을 때**

| 상황 | 레벨 | 무엇을 익히나 |
|---|---|---|
| 못 알아들었을 때 되묻기 | A2 | `Sorry?` `the last part?` `Do you mean ~?` — **반사 속도**가 관건 |
| 잘못된 주문 바로잡기 | B1 | `I think there might be ~` — 정중한 불만의 **완충 표현** |
| 화상회의 기본 | B1 | `You're on mute` `Sorry, go ahead` — 표현이 한정적이라 효율 최고 |

**되묻기를 1순위로 넣은 이유**가 있습니다. 학습자가 실전에서 무너지는 지점은
"내가 할 말을 모를 때"가 아니라 **상대 말을 못 알아들었을 때**입니다. 여기서
굳어버리면 대화가 끝나지만, 되묻기만 반사적으로 되면 나머지가 부족해도 대화는
굴러갑니다.

2주차는 **1주차 진도율이 60%를 넘으면 열립니다**. 잠겨 있어도 `전체 대화`
탭에서는 언제든 미리 볼 수 있습니다.

상황을 추가하려면 `src/data/scenarios/`에 JSON(`week` 필드 포함)을 넣고
`src/data/scenarios/index.ts`에 import만 더하면 됩니다.

## 진도율

"몇 문장을 건드려봤는가"가 아니라 **"어디까지 올라왔는가"**를 잽니다. 문장이
사다리를 한 칸 통과할 때마다 1점이고, 막대는 그 점수의 비율입니다.

```
1주차  ▓▓▓▓▓▓▓▓▒▒▒▒░░░░░░░░░  38%
       파랑=따라 말하기  주황=키워드만  보라=자유롭게
```

색을 셋으로 나눈 이유도 같습니다. 총량뿐 아니라 **어느 단계에 몰려 있는지**가
보여야 다음에 뭘 해야 할지 알 수 있습니다. 이러면 "70문장 다 한 번씩 훑었다"와
"40문장을 끝까지 마스터했다"가 확실히 구분됩니다.

상대역 대사는 `키워드만 보고`가 상한이라 만점이 2점, 학습자 대사는 3점입니다.

## 오늘의 연습

기한이 된 문장을 **상황에 관계없이** 최대 5개 뽑아 각자의 단계로 진행합니다.
복습은 "어느 대화였는지"가 아니라 "언제 다시 볼 때가 됐는지"로 정해져야 하고,
실전에서도 상황은 예고 없이 오기 때문입니다.

5분 안에 끝나야 매일 열게 되므로 세션을 일부러 짧게 잡았습니다. 큐는 세션
시작 시점에 고정되어, 평가한 문장이 진행 중에 눈앞에서 사라지지 않습니다.

## 특징

- **서버·DB·로그인·런타임 API 호출이 전혀 없습니다.** 정적 파일만으로 동작합니다
- 오디오는 [Piper](https://github.com/rhasspy/piper)로 **빌드 타임에 한 번** 생성해 커밋합니다
- 녹음은 브라우저 안에만 저장되고 **어디에도 전송되지 않습니다** (7일 후 자동 삭제)
- 발음 팁은 재사용 라이브러리로 관리하고, 시나리오가 `ref`로 참조합니다

### 기기 내장 TTS를 쓰지 않습니다

브라우저의 `speechSynthesis`(기기 TTS)는 의도적으로 쓰지 않습니다. OS와 브라우저마다
목소리가 달라 학습 기준이 흔들리고, 기계적인 음색을 따라 하면 어색한 발음이 굳기
때문입니다. 모든 음성은 아래 두 모델로 미리 생성한 파일입니다.

| 역할 | 음성 | 특징 |
|---|---|---|
| 상대역 | `en-us-lessac-medium` | Lessac Technologies의 상용 TTS용 스튜디오 녹음. 중립적이고 깨끗합니다 |
| 학습자 | `en-us-ryan-high` | 오디오북 낭독 데이터. 22kHz로 자연스러움이 한 단계 위입니다 |

최소 대립쌍 단어(`right`/`light` 등)도 같이 생성합니다. 이쪽은 **반드시 22kHz**
모델을 씁니다 — 마찰음 차이를 듣는 것이 전부인데 그 에너지가 4~8kHz에 몰려 있어,
16kHz 모델로는 정작 구별해야 할 소리가 잘려나갑니다.

## 시작하기

```bash
npm install
npm run dev          # http://localhost:5173
```

음성 파일은 저장소에 포함되어 있어 바로 연습할 수 있습니다. 시나리오를 새로
추가했다면 아래 순서로 음성을 생성하세요. 파일이 없는 문장은 소리를 내는 대신
화면 상단에 안내 배너가 뜹니다.

### 음성 생성 (최초 1회)

```bash
npm run audio:setup   # piper-tts 설치 + 음성 모델 2개 내려받기
npm run audio:build   # public/audio/<시나리오>/*.mp3 생성
```

- Python 3.9 이상이 필요합니다
- 음성 모델은 **GitHub 릴리스에서 먼저** 받고, 실패하면 HuggingFace로 넘어갑니다.
  HuggingFace가 막힌 망이 흔해서 이 순서로 두었습니다. 둘 다 막히면 스크립트가
  직접 받을 주소를 안내하니 `voices/` 폴더에 넣어주세요
- `ffmpeg`가 있으면 mp3로, 없으면 WAV로 생성합니다. 앱은 둘 다 자동으로 찾습니다

전부 다시 생성하려면 `npm run audio:build -- --force`.

## 모바일에서 소리 나오게 하기

모바일 브라우저에는 데스크톱에 없는 제약이 셋 있고, 셋 다 **"버튼을 눌렀는데
아무 소리도 안 난다"**로 똑같이 나타납니다. `src/audio/player.ts`가 셋 다 처리합니다.

1. **AudioContext는 사용자 제스처 밖에서 만들면 `suspended`로 시작합니다.**
   이 앱은 파형을 그리려고 화면 진입 즉시 오디오를 디코드하는데, 그때 컨텍스트가
   만들어지므로 항상 이 상태가 됩니다. → 문서 전체의 **첫 탭**에 깨웁니다
   (`installUnlock`). 재생 버튼에서만 깨우면 늦습니다.
2. **`resume()`은 비동기입니다.** 기다리지 않고 `start()`를 부르면 아직 멈춘
   컨텍스트에 재생을 걸게 됩니다. Chrome은 대체로 넘어가지만 iOS Safari는
   그대로 무음입니다. → 재생 전에 **resume을 기다립니다**.
3. **iOS는 측면 무음(벨소리) 스위치가 켜져 있으면 Web Audio를 통째로 막습니다.**
   → Safari 16.4+의 `navigator.audioSession.type = 'playback'`으로 우회합니다.
   그래도 안 되면 스위치를 직접 확인해야 합니다.

앱을 백그라운드에 보냈다 오면 iOS가 컨텍스트를 다시 멈추므로, 언락 리스너를
떼지 않고 `visibilitychange`에서도 다시 깨웁니다.

그럼에도 브라우저가 재생을 거부하면 **조용히 넘어가지 않고** 화면에 안내를
띄웁니다 (`AudioSuspendedError`).

> **테스트 주의**: 헤드리스 브라우저에 `--autoplay-policy=no-user-gesture-required`를
> 주면 이 제약이 전부 사라져서 모바일 버그를 못 잡습니다. 오디오 관련 테스트는
> 그 플래그 **없이** 돌려야 합니다.

## 마이크 관련 주의사항

- 마이크는 **HTTPS 또는 `localhost`**에서만 동작합니다.
  폰에서 테스트하려고 `192.168.x.x`로 접속하면 마이크가 막힙니다
  (`mkcert`로 로컬 인증서를 만들거나, 정적 빌드를 HTTPS 호스팅에 올리세요)
- 브라우저의 **잡음 제거·에코 제거·자동 음량 조절을 일부러 꺼둡니다.**
  그 후처리가 `/s/ /f/ /θ/` 같은 마찰음을 깎아내는데, 그건 반드시 직접 들어야 할
  소리이기 때문입니다. 대신 재생할 때 원본과 음량을 맞춰줍니다
- 듣고 나서 말하는 방식이라 **헤드폰이 없어도 됩니다**

## 명령어

| 명령 | 설명 |
|---|---|
| `npm run dev` | 개발 서버 |
| `npm run build` | 타입 체크 + 프로덕션 빌드 |
| `npm test` | 순수 로직 단위 테스트 |
| `npm run validate` | 시나리오·팁 정합성 검증 |
| `npm run audio:setup` | Piper 설치 + 음성 모델 |
| `npm run audio:build` | 오디오 생성 |

`npm run validate`는 다음을 검사합니다.

- 시나리오가 참조하는 팁 `ref`가 실제로 존재하는지
- 하이라이트 `target` 문자열이 문장 안에 실재하는지
- `target`끼리 겹쳐서 팁이 조용히 사라지지 않는지
- 팁이 `why` / `how` / `selfCheck` 3단 구조를 갖췄는지
- 최소 대립쌍이 영어인지 (영어 TTS로 재생되므로)
- `키워드만 보고` 단계에 필요한 `keywords`가 있는지
- `자유롭게 말하기` 단계에 필요한 `intentKo` / `alternatives`가 있는지

```
src/
├── srs.ts                        # 승급·복습 기한·큐 선정 (순수 함수)

│   ├── pronunciation/tips.json   # 재사용 발음 팁 24개
│   └── scenarios/
│       ├── index.ts              # 상황 목록 (추가 시 여기 import)
│       └── *.json                # 대화 시나리오 7개 (주차별)

│   ├── source.ts                 # 오디오 파일 로드 · 최소 대립쌍 단어 재생
│   ├── recorder.ts               # 마이크 (후처리 OFF)
│   ├── normalize.ts              # 음량 정규화·무음 트림
│   ├── player.ts                 # 재생 · A/B/A 시퀀스
│   └── waveform.ts               # 파형 렌더
├── analysis/provider.ts          # 채점을 붙일 자리 (현재 no-op)
├── store/                        # localStorage 진행도 · IndexedDB 녹음
└── components/
    ├── WeekProgressBar.tsx       # 주차별 3색 진도율 막대
    ├── SessionView.tsx           # 오늘의 연습
    ├── TurnCard.tsx              # 대화 목록의 한 줄
    ├── PracticePanel.tsx         # 녹음·비교·평가 (세 단계가 공유)
    └── LevelPrompt.tsx           # 단계별 프롬프트와 정답 공개
```

### 시나리오 추가하기

`src/data/scenarios/<id>.json`을 만들고 `npm run validate`로 검증한 뒤
`npm run audio:build`를 실행하면 됩니다. 팁은 `tips.json`에 있는 것을
`ref`로 참조하고, 없으면 새로 추가하세요.

```jsonc
{
  "id": "turn-id와 파일명이 같아야 합니다",
  "text": "Could I get a large iced americano, please?",
  "ko": "아이스 아메리카노 라지 하나 주세요.",
  "tips": [
    { "ref": "linking-cv", "target": "Could I get a" },  // target은 text에 실재해야 함
    { "ref": "final-stop", "target": "iced" }
  ],
  "coach": "일반 규칙으로 환원되지 않는 이 문장만의 노하우"
}
```

  모드. 문장 단위가 아니라 대화 단위라 화면 구조가 달라서 다음으로 미뤘습니다
